1. Siteswap notation

Juggling happens on a steady pulse. Each beat, one hand throws one object, and the hands alternate: right, left, right, left. A siteswap is one number per beat, and that number answers a single question — how many beats until this object is thrown again?

So a 3 means "this ball comes back to a hand three beats from now". A 5 is thrown higher, because it has to stay up for five beats. The pattern repeats, so 531 means throw a 5, then a 3, then a 1, then start over.

Two consequences fall straight out of that definition:

  • Odd numbers cross, even numbers don't. Hands alternate every beat, so a throw lands in the other hand exactly when its height is odd.
  • The average is the number of balls. 531 averages (5+3+1)/3 = 3, so it is a 3-ball pattern. This is not a coincidence or a rule of thumb — it follows from every ball being thrown once per period.

What makes a siteswap valid

Two balls cannot land on the same beat — one hand, one catch. A throw made at beat i with height a[i] lands at beat i + a[i]. So a sequence is valid exactly when all the values (i + a[i]) mod period are different. 

531  ->  period 3

  beat i    throw a[i]    lands at (i + a[i]) mod 3
  ------    ----------    -------------------------
     0          5                    2
     1          3                    1
     2          1                    0

  landing beats {2, 1, 0} are all different  ->  VALID


521  ->  average (5+2+1)/3 = 2.67, not a whole number  ->  INVALID

The app reports both failures separately, because they mean different things: a bad average means you have written something that is not a juggling pattern at all, while a collision means you have written a real-looking pattern where two balls arrive at once.

The small numbers

ThrowMeaning
0An empty hand. Nothing is thrown, because nothing was there to throw.
1A fast hand-across. Thrown and caught one beat later, so it barely rises.
2A hold. The ball is thrown two beats ahead, which is the same hand's next turn, so in practice you just keep hold of it.

Throws above 9 use letters, so a is 10, b is 11, up to z at 35. The app accepts these, though it caps the graph at height 9.

2. State graphs

A siteswap tells you what to throw. A state tells you what is already in the air — and that is what decides which throws are even available to you next.

Write down the next few beats and mark the ones where something is already scheduled to land. That row of marks is the state. 

state 11100, for 3 balls

  beat:       now    +1     +2     +3     +4
              ---    ---    ---    ---    ---
               1      1      1      0      0
               |      |      |
               |      |      `-- a ball lands 2 beats from now
               |      `--------- a ball lands 1 beat from now
               `---------------- a ball lands NOW: it is in your hand,
                                 so you must throw it this beat

The leftmost digit is the one that matters most. If it is 1 you are holding a ball and must throw it. If it is 0 your hand is empty and the only legal "throw" is 0 — you do nothing and wait.

Making a throw

Throwing does two things at once: a beat passes, and the ball you threw gets booked in for its landing. 

11100  --throw 5-->  11001

  1 1 1 0 0    the leading 1 is the ball now in your hand
   \ \ \ \     one beat passes: everything shifts one step closer
    1 1 0 0    
    1 1 0 0 1  the 5 lands 5 beats out, so set the bit at position 5-1 = 4

  = 11001

If the slot where the ball would land is already taken, the throw is illegal — that is the collision rule again, seen from the other side. This is why each state only offers a handful of throws.

Ground and excited states

With n balls, the calmest possible state is n ones packed at the front: everything lands as soon as it can, nothing is stacked up ahead. That is the ground state, and it is the state a plain cascade lives in. Every other state is excited — you have thrown something high and now have a gap to work around.

For a maximum throw height h, there are C(h, n) states in total: choose which n of the h upcoming beats are occupied. At 3 balls and height 5 that is 10 states; at 5 balls and height 9 it is 126.

Why the graph is shaped like that

The app arranges states in rows by excitation: add up the positions of the set bits and subtract the ground state's total. The ground state scores 0, and higher rows mean more of your future is already committed.

A throw of height t in an n-ball pattern moves you down exactly t − n rows.

So throwing n keeps you on the same row — that's the cascade, sitting still on the ground row. Throwing higher than n pushes you down into excited territory, and throwing lower brings you back up. Since a valid pattern returns to where it started, its throws must balance around n, which is the average rule showing up a third time.

That identity is the whole reason the layout is readable. Rows are not a drawing convenience, they are arithmetic, and you can read a pattern's throw heights off the graph by counting how far each arrow travels.

A pattern is a closed walk. Any loop through the graph that returns to its starting state is a valid siteswap, and every valid siteswap is such a loop. Clicking your way around the graph in the app builds one; typing a pattern highlights it.

3. Ladder diagrams

The state graph shows every possibility but says nothing about time. The ladder diagram is the opposite: it is one pattern, laid out on a timeline.

Two horizontal rails are the two hands. Time runs left to right, one tick per beat. Every throw is an arc from the beat it was thrown to the beat it lands. Because the hands alternate, an arc crosses between the rails exactly when its throw is odd — the crossing is drawn, not asserted. 

531, first six beats

  beat   hand   throw   lands at   in hand   crosses?
  ----   ----   -----   --------   -------   --------
    0      R      5         5         L      yes
    1      L      3         4         R      yes
    2      R      1         3         L      yes
    3      L      5         8         R      yes
    4      R      3         7         L      yes
    5      L      1         6         R      yes

  every throw in 531 is odd, so every arc crosses
  -- that is what makes it a cascade


441, first three beats

  beat   hand   throw   lands at   in hand   crosses?
  ----   ----   -----   --------   -------   --------
    0      R      4         4         R      no
    1      L      4         5         L      no
    2      R      1         3         L      yes

What the ladder makes obvious is overlap. At any moment you can count the arcs passing overhead, and that count is the number of balls — which is why a valid pattern's average has to be a whole number.

The connection to the state graph

Here is the part worth internalising, because it is the reason the app shows both diagrams at once.

A state is a vertical slice of a ladder diagram. Drop a line at beat k. The arcs crossing that line are the balls in the air. Measure how far ahead each one lands, and those offsets are exactly the set bits of the state at beat k. 

531, cursor at beat 3

  thrown at    height    lands at    offset from beat 3
  ---------    ------    --------    ------------------
      0           5          5              +2
      1           3          4              +1
      2           1          3              +0

  offsets {0, 1, 2}  ->  bits 0, 1 and 2 set  ->  state 11100

Hover any beat on the ladder in the app and it does this live: the crossing arcs thicken, the state string under that beat lights up, and the matching node in the state graph is ringed.

The faint dashed arcs at either end are throws made before the window starts or landing after it ends. They are drawn because without them the slice at beat 0 would appear to cross nothing, while its state plainly says three balls are airborne.

4. How the three line up

The same pattern, in three registers. Each view answers a question the other two cannot.

ViewAnswersBlind to
Animation What does it look like? How high is each throw? Structure — why these throws and not others
Ladder What happens on each beat, and which balls overlap? Everything you did not throw
State graph Where else could this pattern have gone? Time — a walk has no tempo

They are locked to one beat counter. Play the animation and the ladder cursor advances with it while the state graph lights the node you are standing on. Pause and hover a beat to scrub all three at once.
